Architecture

Three minds. One grounded answer.

Like a medical conference, three specialists examine the question from different angles, then deliver one careful synthesis. Analyst checks the facts. Humanist reads the room. Skeptic asks what's missing.

Fusion architecture

Three local GGUF models, Analyst, Humanist, Skeptic, each examine your query from a different angle. Their perspectives are scored by core weights derived from query type, cross-probed against each other for weak claims, then synthesized into one answer. Model-stated confidence is exposed when available.

Local-first

Local inference runs on your hardware via llama.cpp. Conversations, vault and memory are stored on the device running the local edition. Model downloads and optional network tools have separate network requirements.

Evidence vault

Local knowledge base with tiered sourcing. Cross-encoder reranking. Citations enforced as [Vault:Source] with strict-mode checking.

Anti-consensus Skeptic

The Skeptic argues against the strongest emerging consensus between the other two cores, not against the user. Catches the place where smart panelists agree without checking each other.

Confidence made visible

Confidence signals can include evidence-derived estimates, model-stated confidence and a blended value, when available. They help inspect an answer; they are not proof that it is correct.

Proof

Built to be checked.

ZOTHEOS includes signed result receipts, local forecast records, evidence-linked corrections and backend network checks. They make the work inspectable, and their desktop integration is part of the current validation.

01

Signed receipts

Verify result-receipt signatures offline. A signature check establishes whether the receipt matches its signing key; it does not prove the answer is correct.

02

Prediction ledger

Forecasts the system logged, scored against what actually happened. A local track record with a reliability diagram.

03

Belief drift

When the council changes its mind, the full chain stays: v1 to v2 to v3, with the evidence that moved it. No memory-holing.

04

Corrections in the open

Every flagged correction is kept with provenance in an immutable log, and approved or rejected where you can see it.

05

Backend network checks

A backend network ledger and canary check make backend controls inspectable. They do not establish that every desktop-shell or WebView2 connection is blocked.

ZOTHEOS also measures its own catch rate. The method is published; the numbers print when they are ready, not before.

What can I bring?

Compatible chat models in GGUF format. GGUF is the model-file format used by the local engine. Supported model architecture, available memory and the model's license determine what can run.

Hugging Face, GitHub or elsewhere?

Model Setup searches Hugging Face. A compatible file obtained from GitHub or another legitimate source can be imported locally. The built-in browser is not a general GitHub downloader.

Mission

The internet became a casino.
This is the library.

ZOTHEOS is built to strengthen human judgment, to guide rather than govern. The Analyst examines evidence, the Humanist keeps human consequences in view, and the Skeptic checks assumptions. You remain free to question the answer, disagree and decide.

Keep knowledge accessible. Keep privacy intact. Keep human agency at the center.

Universal peace is a moral horizon: knowledge, empathy and cultural memory in service of human dignity. It is not a promise that software can impose peace or make people obey.

Evolved Intelligence is a research direction toward accountable learning, useful self-correction and understanding. It is not a claim of consciousness, infallibility or absolute truth.

Responsible computation means making useful use of existing models and hardware, choosing appropriate workloads and measuring resource costs. Local AI still has an energy and hardware footprint; environmental benefit must be measured, not assumed.

Frequently asked

Questions worth asking.

Does ZOTHEOS actually work offline?
Local inference runs via llama.cpp once the required models are available. Model downloads and optional network features need a connection. The local edition stores conversations and vault files on your device.
Why three models instead of one larger one?
Analyst, Humanist, and Skeptic examine questions from different angles, then synthesize an answer that can expose evidence and disagreement. Multiple models can share the same error, so agreement is not proof.
What hardware do I need?
ZOTHEOS is being developed for broad hardware access, including desktops, laptops, mini PCs, older computers and kiosks. Current desktop release testing focuses on Windows x64. Processor support, memory, storage and model compatibility still matter; compact-system startup and other platforms remain in development.
Is any of my data collected?
The local edition stores conversations, vault and memory on the device running it. This website sends waitlist emails to Formspree for milestone updates, and loads hosted fonts and media. Local inference and website processing are separate.
How is ZOTHEOS funded?
Development is independent and self-funded, with optional support. The local edition is free for individual use. Support does not unlock features, access, priority or influence. Institutional deployment and support may be paid; they are not required for individual local use.
What is the "evidence vault"?
A local, tiered knowledge base the council can cite. Retrieval can rerank sources, and strict mode checks grounding and citation tags. A citation still needs to be inspected against its source.
How do I know it is really offline?
The backend includes a network ledger and a canary check for its network controls. Those checks cover backend activity, not every shell or WebView2 connection. Receipt signatures can be checked offline, separately from network behavior.
What happens when ZOTHEOS is wrong?
Flagged corrections are recorded with provenance for review. Belief-drift records retain evidence linked to a change. These records make changes inspectable; they do not prove that an answer is correct.
Can kids use ZOTHEOS?
Kids Mode is not enabled in the current product. Age-band support remains planned.
What is the Smart Board?
An AI whiteboard with council prompts, document tools, charts, voice and conversation saving. Available functions depend on the configured models and tools.
Can I choose my own models?+
Yes. Model Setup browses Hugging Face and imports local GGUF files, so starter packs are a beginning rather than a fixed catalog. Compatible chat models can be assigned to the council roles. Each model retains its own license, and runtime support plus available memory determine what can run. GitHub files can be imported locally when compatible; an integrated GitHub downloader is not established.
